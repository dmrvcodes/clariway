# Progress: 19 November 2026

## Scope completed

- Manifest V3 side panel with Chrome 139 minimum version.
- User-triggered page access through `activeTab` and `scripting`; no blanket host
  permissions or permanent content script.
- Runtime validation of all page-context messages with Zod.
- Local extraction of page title, meta description, selected text, up to 6,000
  characters of main content, and up to 500 characters of nearby context per
  image.
- Local audit of the first 50 images with three evidence-based states:
  described, missing a text alternative, or intentionally ignored by screen
  readers.
- Detection of unlabelled linked or button images.
- English text-to-speech with voice selection and stop handling.
- Firebase AI Logic diagnostics for `ONLY_ON_DEVICE` and `ONLY_IN_CLOUD`, with
  the actual inference source shown in the UI.
- Firebase App Check debug-provider bootstrap and setup instructions.

## Verification

Run:

```bash
npm run verify
```

The command performs a strict TypeScript build, creates the production extension,
validates its manifest and executable files, confirms the injected content script
is standalone, and executes that built script against a representative HTML page.
The smoke scenario covers described, missing, ignored, and unlabelled interactive
images plus page and nearby-text extraction.

The same build and smoke check pass on the supported Node.js 24.12 runtime.

## External acceptance

Tested in desktop Chrome against the W3C Before and After Demonstration
inaccessible home page:

- unpacked `dist` loads and the toolbar action opens a tab-scoped side panel;
- the toolbar reports that Clariway has temporary access to the current site;
- page context extraction completes with `Page context ready`;
- the audit inspects all 42 images and reports 36 missing text alternatives;
- described and unlabelled interactive images are distinguished in the report;
- selected English text is captured after an audit, spoken with the selected
  system voice, and stopped through `Stop speaking`;
- both AI diagnostic controls fail closed with an actionable App Check setup
  message while `.env.local` is intentionally absent.

The test exposed a Chrome integration regression: `openPanelOnActionClick` is
persisted across extension reloads and prevented the explicit action handler
from receiving the user gesture needed for `activeTab`. The background worker
now resets that persisted behavior, opens the panel from `action.onClicked`, and
has a build-level regression test for a granted tab whose URL is not exposed.

## Remaining Firebase acceptance

- A private `.env.local` now enables the local App Check debug provider. It is
  ignored by Git.
- The development token is registered in Firebase App Check as `Clariway Chrome
  local`. The secret itself is not recorded here or in source control. Firebase
  accepted a subsequent debug-token exchange with HTTP 200.
- Re-open the unpacked extension after App Check propagation and verify that
  `ONLY_ON_DEVICE` and `ONLY_IN_CLOUD` return the expected inference sources in
  the UI.
- Enable Firebase AI Logic for `clariway-1262e` if either diagnostic reports a
  backend activation error.

The extension console reports an expected remote reCAPTCHA script CSP warning
in debug mode. App Check still generates and exchanges the registered debug
token; a public extension release must replace the debug path with a
Chrome-compatible production attestation design and remove
`VITE_APP_CHECK_DEBUG=true`.
