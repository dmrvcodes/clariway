# Progress: 21 November 2026

## Scope completed

- Local audit of the first 20 `<audio>` and `<video>` elements on the current
  page with no additional extension permissions.
- Three explicit media-accessibility states: caption track available,
  transcript available, or missing captions/transcript.
- Detection of author-provided `captions` and `subtitles` tracks, including
  language, label, mode, and loaded cue count.
- Detection of transcripts exposed through `aria-describedby`, inline
  transcript containers, or explicit transcript/caption links.
- Extraction and normalization of loaded text-track cues into a bounded local
  transcript preview.
- Side-panel media report with totals, per-element evidence, track languages,
  duration when available, and a missing-text-alternative count.
- English TTS for an available transcript, reusing the existing voice selector
  and stop behavior.
- Runtime schema validation for the complete media audit added to `PageContext`.

## State model

```text
audio/video
  ├─ captions/subtitles <track> exists → captioned
  ├─ inline/linked/ARIA transcript exists → transcript
  └─ neither exists → missing
```

Caption-track presence and transcript presence are kept separate from cue
availability. A cross-origin or not-yet-loaded track can be correctly reported
as captioned even when the browser does not expose its cue text to Clariway.

## Deliberate limits

- This scope audits author-provided accessibility data; it does not record tab
  audio or perform speech-to-text.
- Cross-origin text-track metadata can be audited, but cue text may remain
  unavailable because of browser/CORS restrictions.
- Linked transcript pages are reported as evidence but are not fetched or sent
  to Firebase.
- Live caption generation and tab-audio capture are deferred to a separate
  privacy and permissions design.

## Cloud only with explicit consent

This replaces the automatic `PREFER_ON_DEVICE` cloud fallback from 20 November.

- Image descriptions use two Firebase AI Logic model instances:
  `ONLY_ON_DEVICE` by default and `ONLY_IN_CLOUD` only after the user approves.
- If on-device AI is unavailable or fails, nothing is sent. The image card
  shows the exact crop, page title, page description, nearby text, image size,
  and whether the image is interactive, with **Send to cloud** and
  **Don't send**.
- On-device results offer **Ask the cloud model instead** behind the same
  consent step.
- `describeImageInCloud` accepts only a `CloudConsent` created by that click.
  It carries a frozen copy of the approved fields and nothing else.
- `@firebase/ai` 3.1.0 creates its on-device adapter only when `LanguageModel`
  is truthy; without it, `ONLY_ON_DEVICE` requests go to the cloud. Clariway
  checks first and fails closed.
- On-device inference runs on a separate Firebase app instance without App
  Check, so local work sends no Firebase request and works without
  `.env.local`.
- Keyboard focus moves to the consent card or the result after each step.
- Local text-to-speech voices are listed first; network voices are labelled.

### Manual acceptance in Chrome (pending)

1. Run `npm run build` and reload `dist` in `chrome://extensions`.
2. Click **Test on-device AI** and expect `AI ready via on device`.
3. Click **Test cloud AI** and expect `AI ready via in cloud`.
4. Open a page with a visible image missing `alt`, audit it, and click
   **Describe this image**. Expect the **On device** badge. In the side panel's
   DevTools (right-click the panel, **Inspect**), the Network tab shows no
   request to `googleapis.com`.
5. Click **Ask the cloud model instead**, review the card, then
   **Send to cloud**. Expect the **Cloud · Gemini** badge.
6. Click **Apply preview fix**, then **Undo preview fix**.
