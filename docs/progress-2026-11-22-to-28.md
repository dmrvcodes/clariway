# Implementation and acceptance: 22–28 November scope

The code and documentation scope scheduled through 28 November was completed
ahead of the external submission work. No commit, push, deployment, billing
change, public repository, or video upload was performed.

## Delivered

- Reversible per-tab reading comfort: 100/125/150% scale, higher contrast, and
  stronger focus visibility. Reset removes only Clariway-owned state and CSS.
- Local TTS for a freshly-read selection or bounded main-page English text.
- Session-only routing evidence: successful on-device results and explicit
  cloud-send approvals, reset on a new audit.
- Stable Firebase project-access and rate-limit errors without exposing raw
  transport details to the user.
- A security/privacy model, cross-browser/mobile boundary, demo script,
  submission copy, and release checklist.
- A 45-second on-device inference timeout. The Firebase/Chrome local generation
  API does not currently expose cancellation through this integration, so the
  underlying SDK task may finish later; Clariway releases its UI wait, sends
  nothing, and prepares an explicit consent card. A batch does not retry the
  failed local runtime for each remaining image.

## Automated gate

`npm run verify` builds the production extension and covers bounded audits,
schema validation, crop geometry, malformed model output, fail-closed routing,
timeout recovery, immutable consent, reading-profile apply/reset, routing
counters, DOM Apply/Undo, and the absence of `PREFER_*` inference modes.

Docker is not part of the application runtime: Clariway has no server, and the
Chrome extension, `activeTab`, Prompt API, side panel, and local TTS need the
real browser. It was used only as an isolated build gate because the host shell
has Node 22 while the project declares Node `>=24.12`. A clean Node 26.12
container install, build, regression suite, and production dependency audit
passed against a read-only source mount.
